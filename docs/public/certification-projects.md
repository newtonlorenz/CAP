# Organise a certification engagement

Start in **Certifications**. Give the project a name, market and intended scope.
You can record a test lab or audit provider immediately and choose approved requirements
later. A project without a baseline shows the next action; an assessment cannot begin
until approved requirement versions have been selected.

The five sections follow the work:

- **Overview:** project stage, outstanding work and next action. Stage checks remain advisory.
- **Requirements and evidence:** the pinned baseline, requirement assessments and supporting
  forms. Create private form questions here, import reviewed questions or use a saved blank form.
- **Testing and findings:** provider, scope, system version, engagement reference and test dates;
  milestones and links to assessment findings.
- **Reports and submission:** recorded provider report reference, outcome and link, plus internal
  package preparation, approval and locking. A provider result does not record authority approval.
- **History:** previous assessments, package versions and manual maintenance plans.

An engagement can cover several approved requirement sets. Updating source requirements
never silently changes its pinned baseline or completed assessments. Compare versions
and use explicit migration when the baseline needs to change. Project-linked maintenance
assessments use that pinned baseline and retain links to previous results.

Project access applies to linked forms, evidence and assessments. Assigning an owner does
not grant access. Share work through its access controls and choose view, edit, approval
and export permissions deliberately. Restricted project details are hidden from users
who can only see a related change.

For Denmark, check the applicable certification programme before licence issue. For
Finland, distinguish preparation of the licence application from the audits and
integrations required before operation. These market obligations are guidance, not CAP
stage gates or an automatic legal determination.

### Adding a project form

In **Requirements and evidence**, choose **Add form**. The editor opens in a dialog
and links the created form to this project. Failed creation retains your entries.
Closing a changed draft asks before discarding it; cancelling that confirmation
returns to the editor. Reusable template maintenance remains under Resources.
